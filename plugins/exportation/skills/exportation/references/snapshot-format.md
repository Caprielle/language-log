# 本地读取快照协议 v1

本协议只用于连接经过验证的真实消息读取工具与转换脚本。它不是 ChatGPT API，不授予历史访问权限。当前包不含读取工具或适配程序；适配程序必须在取得真实工具返回结构后编写并验证，不猜字段或模拟消息。不能让模型根据聊天印象生成下面的 JSON。

快照是 UTF-8 JSON 对象，重复 JSON 键会报错。顶层字段全部必填，不接收未知字段：

| 字段 | 要求 |
| --- | --- |
| `schema_version` | 整数 `1` |
| `source` | 固定 `chatgpt-conversation` |
| `conversation_id` | 真实 ID 或 `unknown`，1 至 100 个字母、数字、下划线、连字符 |
| `title` | 原始标题；确实无法取得时为空字符串，不生成标题 |
| `reader` | 实际读取工具名称，非空字符串 |
| `read_reference` | 真实读取操作或结果的可回查引用，非空字符串 |
| `has_more_before` | 原始工具确认没有更早消息时为布尔值 `false` |
| `has_more_after` | 已读到本次导出请求、没有遗漏该范围内后续消息时为 `false` |
| `truncated` | 原始结果没有截断时为 `false` |
| `export_request_id` | 本次真实导出请求的消息 ID |
| `messages` | 当前分支的全部用户可见文字消息，按顺序排列，最后一条为本次导出请求 |

每条消息恰好包含以下字段：

| 字段 | 要求 |
| --- | --- |
| `id` | 真实、非空、全篇唯一的消息 ID |
| `parent_id` | 前一条可见消息的真实 ID；首条为 `null`。适配程序必须根据真实分支关系确定可见消息的前后关系 |
| `role` | `user` 或 `assistant`；允许同一角色连续出现 |
| `content_type` | 固定 `text` |
| `content` | 原始文本，允许空字符串；不得转换为字符串、总结、规范化或重新生成 |
| `status` | 读取工具确认消息完整时为 `complete` |

首条必须是用户消息；至少有一条先前用户消息和最后一条导出请求。最后一条必须是 `user`，ID 必须等于 `export_request_id`，输出时排除。不得要求助手回复必须与用户消息严格交替。

系统、隐藏推理、工具内部消息不属于可见问答，不纳入此协议；适配程序必须先核实原始读取结果的消息类别，不能仅凭空内容猜测并丢弃消息。分支缺失、非文字内容、未知消息类型或分页状态不明时，适配程序应失败，不能伪造协议字段。

`false` 标志、工具名、调用引用和链路都只是快照记录。转换器校验这些结构，但不认证它们的真实性，不提供 ChatGPT 账号完整性证明。只有真实工具结果及适配程序的验证，才能支撑完整原文声明。

输出文件头记录来源、原始标题、聊天 ID、北京时间、真实消息边界、消息数量、读取工具及引用、源快照 SHA-256，以及各条正文的长度与校验值。正文用长度明确且可逆的 Markdown 文本块表示；校验值用于核对转换结果，不用于证明源聊天没有遗漏。
