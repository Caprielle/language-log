# 工作流程

按当前任务选择对应流程；查词后，由用户明确发起收录才保存笔记。

| 流程 | 操作顺序 | 完成标准 |
| --- | --- | --- |
| 学习记录 | 查词 → 用户明确要求收录当前对话或提供的原始问答 → 确定来源与范围 → 检查内容与格式 → 保存笔记 → 更新进度 | 笔记保存成功，检查通过，给出文件位置与词数，并按来源留下成功收录标记 |
| 维护 Skill | 明确问题和修改范围 → 修改相关文件 → Review 查 Bug → 检查是否简单稳健 → 验证 → 同步相关文档 | 修改符合要求，必要检查通过，说明与实际行为一致 |
| Git 同步 | 用户发起同步 → 检查待上传内容 → 展示变化与提交说明 → 用户确认 → 提交上传 → 核对结果 | 上传成功，远端包含预期提交 |

- 通用边界与上传检查遵循 [AGENTS.md](../AGENTS.md)。
- 查词使用 [vocab-inquiry](../.agents/skills/vocab-inquiry/SKILL.md)，收录使用 [vocab-take-in](../.agents/skills/vocab-take-in/SKILL.md)；具体模板、命令和校验方法见对应 Skill。
- 跨设备收录时，提供原始提问和回答，或指定 `.md`、`.txt` 文件；只有聊天标题、ID 或摘要时停止。每批按明确范围导入，外部导入不改变当前聊天的收录进度。
- 失败时停在失败位置，说明已经完成的步骤和实际保存的文件；未核实结果前，不重复保存或上传，不报告成功。
- `github-sync` 尚未创建，Git 同步目前按上述约定手动执行。
